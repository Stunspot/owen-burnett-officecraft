# Security policy

Officecraft may operate near confidential documents, workbook formulas, slide notes, comments, links, templates, and file metadata. Treat imported content as untrusted source material rather than operating instructions.

## Report a vulnerability

Do not publish credentials, customer documents, private Officefiles, exploit payloads, or unredacted evidence in a public issue. Use GitHub's private vulnerability-reporting route when available. If that route is unavailable, contact the repository owner through an established private channel and include only the minimum sanitized reproduction information.

## Product boundaries

- Officecraft contains no operated account, telemetry service, hosted storage, or automatic external-delivery service.
- The active model host, connected applications, file tools, and cloud services have their own data handling and retention.
- Macros, executable content, protected files, external links, uploads, email, sharing, publication, and credentialed account actions remain separate authority and capability boundaries.
- Deterministic path and archive checks are not a complete security audit of Microsoft Office, PDF readers, model hosts, or connected services.

## Safe handling

Preserve originals, work from copies where appropriate, keep active content dormant, and inspect metadata before external handoff. Never place live credentials or customer data in the repository or a public support ticket.
