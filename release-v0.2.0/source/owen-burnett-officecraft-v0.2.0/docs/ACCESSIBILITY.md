# Accessibility

Officecraft's core production handoff can remain textual: brief, source manifest, content ledger, artifact specification, quality checklist, review record, and handoff receipt. A missing renderer does not require an image-only fallback.

## Documentation design

The public site and generated documentation use semantic headings, labelled navigation, skip links, visible keyboard focus, descriptive links, responsive layout, reduced motion, and text alternatives for informative imagery. Commands, paths, statuses, and acceptance language remain copyable text. No instruction depends only on color, animation, audio, or an image.

## Artifact accessibility

Officecraft directs authors to use meaningful document hierarchy, real lists and tables, readable type, clear labels, adequate contrast, chart units and context, informative-image descriptions, meaningful reading order where supported, and non-color cues. These are production requirements, not proof that an artifact passed them.

Name the check actually performed: structural heading review, contrast calculation, rendered page inspection, slide reading-order inspection, workbook label review, PDF accessibility inspection, or native accessibility check. Do not promote one check into formal conformance.

## Review status and gaps

The public documentation receives a separate source and rendered-structure review. Screen-reader traversal, voice control, magnification, forced colors, native Office accessibility checkers, PDF tagging inspection, and representative-user completion remain untested unless a receipt explicitly states otherwise. No WCAG conformance claim is made.

Report a barrier through [Support](SUPPORT.md) with the page or operation, host/version, assistive technology when relevant, expected route, observed barrier, and a privacy-safe reproduction.
